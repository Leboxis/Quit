# V3 — Comprendre les écarts et alléger l’interface

## Parcours implémenté

1. **Juste avant** : date, contexte et émotion. Les choix sont explicites, sans émotion préremplie pour une nouvelle analyse.
2. **Repérer le début** : déclencheur et premier moment où agir. Une phrase locale adaptée peut être utilisée ou remplacée ; le texte libre est facultatif.
3. **Choisir la suite** : proposition Si → Alors éditable, ajout ou mise à jour d’une règle uniquement avec accord explicite, et retour au plan facultatif.

Environ 60 secondes est un objectif de conception, pas une durée mesurée ni un compte à rebours. Les gestes proposés viennent de règles locales transparentes, sans serveur, apprentissage automatique ni diagnostic. Ils ne sont pas des prédictions de risque.

Les commandes Continuer/Enregistrer restent en bas hors du défilement. Retour conserve le brouillon. Fermer demande confirmation ; le glissement de fermeture est désactivé tant que l’analyse n’est pas enregistrée. Une erreur de sauvegarde reste visible dans la feuille et conserve le brouillon. Après enregistrement, l’utilisateur peut renseigner la reprise du plan ou simplement terminer.

## Audit de l’espace : décisions

| Écran | Encombrement constaté | Changement |
| --- | --- | --- |
| Accueil | Illustration de 72 points, grand en-tête, carte séparée pour l’intention | Illustration retirée ; accueil compact ; intention regroupée et dépliable |
| Analyse | Tout le formulaire et textes de réassurance affichés ensemble ; grande illustration finale | Trois étapes ; un sujet à la fois ; confirmation courte sans artwork |
| Journal | Épisodes tous affichés ; types regroupés au lieu d’un fil chronologique ; suppression permanente | Historique mixte, filtres menu, pagination par 20, LazyVStack, détails dépliables et menu de suppression |

Pas de réduction globale des tailles de police ni des zones tactiles pour gagner de la place. Le check-in, les plans et l’accès SOS existant restent disponibles. L’espace gagné n’est pas chiffré sans rendu natif sur appareil. Les statistiques, le SOS et les autres écrans ne sont pas refondus dans cette passe V3.

## Corrections

- L’action Alors est enregistrée dans l’épisode et rechargée à l’édition, même si aucune règle n’est créée.
- L’épisode conserve l’identifiant du plan associé ; son actualisation est volontaire et ne crée pas un doublon. Une règle strictement identique peut être réutilisée.
- À 100 règles, une nouvelle règle n’est pas proposée ; l’analyse seule reste enregistrable. La couche de données protège aussi le plafond de façon atomique.
- Les interruptions historiques restent autorisées jusqu’à 2 000 caractères ; la limite de 500 caractères concerne uniquement les règles.
- Une récupération historique n’est pas déplacée silencieusement : le sélecteur de date est borné et la couche de données refuse une date postérieure au retour renseigné.
- L’initialisation du brouillon ne se répète pas à chaque apparition. Un épisode disparu ne devient pas une nouvelle création silencieuse au moment de l’enregistrement.
- Le script de distribution utilise des chemins POSIX pour les membres ZIP, même sous Windows, afin de retrouver l’exécutable dans l’IPA.

## Données et confidentialité

Les nouveaux champs nextAction et planID sont optionnels ; les JSON V1/V2 sans ces champs sont décodables. Le schéma, les UUID, le fichier local et l’identifiant de l’app restent inchangés. Ce contrat est une compatibilité de lecture des anciennes sauvegardes, pas une garantie de réexport sans perte depuis une ancienne app. Supprimer une analyse ne supprime pas une règle personnelle déjà choisie ; supprimer une règle ne supprime pas l’analyse.

## Figma

Référence fournie : [Quit — Reprendre le contrôle](https://www.figma.com/design/5wrVQf5TcnIVAJmnLN8ePs?node-id=14-232).

Le lien a été retrouvé et ouvert sous forme HTML ; les calques, écrans et composants n’ont pas été inspectés ou modifiés. Aucun outil Figma n’est exposé dans la session. Il faut un connecteur Figma compatible pour créer des frames éditables ; cette implémentation ne revendique donc pas une reproduction pixel-perfect de la maquette.

À transposer dans Figma une fois connecté : accueil compact/intention fermée et ouverte, trois étapes de l’analyse, règle acceptée/refusée, plafond de plans, erreur disque, confirmation de sortie, analyse enregistrée, journal filtré/déplié/vide/chargement supplémentaire. Vérifier les états Sauge/Brume/Sable, clair/sombre, iPhone étroit et iPad, puis comparer au rendu natif.

## Validation

- 11 tests XCTest V3 ajoutés : fixtures JSON brutes V1/V2, persistance/export des nouveaux champs, action seule, règles/UUID/déduplication, texte long, limite des plans et rollback, récupération historique et suggestions.
- Un scénario UI ajouté : créer l’analyse, accepter une règle, reprendre le plan, rouvrir/éditer, vérifier le prochain geste et retrouver l’épisode après relancement. Captures natives enregistrées comme pièces jointes XCTest quand il s’exécute.
- Régressions Python ajoutées pour les chemins POSIX des archives et le refus de traversée de chemin.
- Validation des ressources réussie : 42 exercices complets, assets valides et déclaration sans tracking. git diff --check réussi. Les deux tests Python de contraste réussissent.
- La suite Python de distribution a d’abord révélé le bug de séparateurs de chemins ZIP, corrigé dans le code. Sa relance complète après correction reste bloquée en accès confiné par les permissions des répertoires temporaires Windows. Le diagnostic autorisé hors confinement n’a modifié aucune permission et n’a pas trouvé de réparation applicable. Le rapport de diagnostic reste local et n’est pas inclus dans le dépôt.
- Swift/Xcode absents sous Windows : compilation, XCTest, UITest, inspection visuelle et mesure de temps restent à exécuter sur Mac. Le workflow séparé Native reliability validation lance les tests XCTest/UI sur deux tailles d’iPhone, la nuit ou sur workflow_dispatch ; le workflow de publication rapide compile pour appareil et n’exécute pas ces tests natifs.
